# Internationalisation

This page documents the current i18n behavior. It is a status document, not a
claim of complete localisation or full Unicode rendering parity.

## Locale selection

The CLI accepts a global locale override:

```bash
kumeyuri --lang ja-JP compat
kumeyuri --lang en_US.UTF-8 render diagram.mmd --format text
```

Locale resolution order is:

1. `--lang <locale>`
2. `LC_ALL`
3. `LANG`
4. `en-US`

Locale tags are normalized before parsing:

- `en_US.UTF-8` becomes `en-US`.
- Locale modifiers after `@` are ignored.
- `C` and `POSIX` locales fall back to `en-US`.

Invalid locale tags fail fast before the subcommand runs.

## Message resources

CLI-facing strings are routed through Fluent IDs in `locales/en-US.ftl`.

Current limitation: only the embedded `en-US` resource ships today. Passing
another valid locale tag configures the Fluent bundle locale, but output text
still uses the embedded English messages until translated resources and
resource selection are added.

The web component, npm integration packages, docs, and generated diagram text
are not localized.

## Text layout

Core layout uses Unicode-aware helpers from `kumeyuri_core::unicode` for the
paths that have been migrated:

- display-cell width via `unicode-width`;
- grapheme-safe truncation and wrapping via `unicode-segmentation`;
- a BiDi visual-order pass via `unicode-bidi` before text is written to frames.

`--max-label-width` wraps labels by display-cell width and preserves grapheme
clusters. Snapshot coverage exists for BiDi, CJK, and emoji inputs.

Current limitation: the final `Frame` is still a grid of `char` cells. Some
frame, animator, and renderer code paths still derive positions from character
counts. See `docs/i18n-width-audit.md` for the current audit boundary.

## Raster font fallback

Raster output first uses built-in bitmap glyphs where available. On native
targets it then tries system fonts in this order:

1. `Noto Sans`
2. `Noto Sans CJK`
3. `Noto Sans Arabic`
4. `Noto Color Emoji`

If those fonts are not installed, unsupported glyphs may be omitted from raster
output. WASM builds do not have system font fallback.

## Known limitations

- No non-English Fluent resources are bundled yet.
- Locale choice does not change diagram parsing, Mermaid compatibility, date
  formatting, number formatting, or theme names.
- Mermaid `accTitle` and `accDescr` are not parsed into localized accessibility
  metadata.
- SVG text output depends on the consumer's fonts for glyph coverage.
- Terminal output depends on terminal font, shaping, width, and BiDi behavior.
- Complex scripts and emoji ZWJ sequences are covered by snapshots, but exact
  visual rendering still depends on the output backend.
