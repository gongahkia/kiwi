# Vi navigation qualification — 2026-10-25

This is evidence for Kiwi's bounded navigation/selection subset, not full terminal
parity or general displayed-latency qualification. The seven-workstream scope
remains in the [implementation ledger](../IMPLEMENTATION_TRACKER.md).

## Implementation and reproducibility

Atomic changes: `0c54eb7` indexes retained rows; `14ba042` adds the vi model and
rectangular rendering; `b54dbf3` connects host input/Find; `9fef883` bounds wrapped
selection expansion; `7c809ad` bounds copy buffers and reuses row views;
`5034d93` adds lifecycle/limit tests and CI gates; `d11015e` reveals offscreen link
targets; `9928aac` preserves inline-find identity; `6465309` keeps Find limits and
stale/no-match statuses visible in vi mode.

Commands:

```sh
make check test-core
make vi-smoke selection-smoke
make bench-navigation NAVIGATION_HISTORY=10000
```

The native smokes require a graphical session. They use private clipboard data
and disable saved-layout restoration/persistence. The vi fixture drives the actual
host callbacks and controller while a raw Python child records every PTY input
byte. Only the deliberately typed `x` after vi exits may reach the child.

Vi tests cover grapheme cells, combining text, hard/soft wraps, counted motions,
preferred columns, bracket/inline find, character/line/word/block selection,
clipboard limits, work caps, cancellation, configuration transaction copies,
history eviction, primary reflow and alternate-screen changes. A seeded test
mixes 500 output/resize/screen/motion/selection transitions. Input tests include
IME routing, repeats/releases after exit or pane changes, global shortcut
ownership, relative forward/backward regex Find, visible result limits and
explicit hyperlink activation after the retained cursor leaves the viewport.

The GPU fixture measures exact red-pixel coverage on a concealed-text scene:
a rectangle covering six ordinary cells expands to seven cell areas because it
touches a wide character in the middle row. It then verifies an 18-cell linear
range and zero highlighted pixels after clearing. This establishes WGPU coverage;
the GTK GL pass has no separate pixel-readback result. Xvfb's DRI3 warnings reflect
software rendering; that run does not qualify hardware acceleration or a desktop
compositor. GTK accessibility-bus warnings in the GL lifecycle smoke do not
establish an accessibility result.

## Retained-history workload

Raw records: [macOS](2026-10-25-vi-macos.json),
[Linux](2026-10-25-vi-linux.json). Both use the benchmark code at `5034d93`.
macOS records a clean checkout. Linux used `git archive 5034d93` in `/work`, with
the full hash saved in `BUILD_REVISION`; its raw environment probe cannot determine
Git metadata because the archive has no `.git` directory.

The fixture has 10,000 history rows plus 24 screen rows, 80 columns, and one
801,920-character soft-wrapped word. It measures CPU/model work, not terminal
startup, GPU submission, input-to-display latency or scheduler sleeps. Construction
and copy verification are outside the scan timings. Each case is one run including
its initial JIT/setup cost, not a repeated statistical comparison to competitors.
Final macOS and Linux measurement runs were sequential with no concurrent Kiwi
test workload. The Linux container had two CPUs and a 4 GiB memory limit.

| Case | macOS p95 slice CPU | Linux p95 slice CPU | macOS total CPU | Linux total CPU |
| --- | ---: | ---: | ---: | ---: |
| Word-end motion | 0.79 ms | 0.93 ms | 114.0 ms | 127.5 ms |
| Expand logical-line selection | 1.28 ms | 2.39 ms | 3.4 ms | 6.2 ms |
| Expand word selection | 0.96 ms | 1.16 ms | 143.3 ms | 166.0 ms |

Each scan slice stayed at or below 4,096 work units. Line expansion used 10,025
units total; word motion/selection used 801,921 each, below the 8,388,608 job cap.
Maximum sampled temporary heap across these cases was 1.39 MiB on each platform.
After cancelling a pending selection and collecting, the extra retained heap was
730 KiB on macOS and 740 KiB on Linux. Cancellation measured approximately 0.002 ms
and 0.001 ms, respectively; those tiny single samples are not a latency guarantee.
The benchmark asserts bounded work, temporary heap below 16 MiB, retained growth
below 1 MiB, complete selection/copy length and no copyable partial selection.
A separate 1,000-row interpreter-only diagnostic passed after row-view reuse.

The terminal model itself still occupied approximately **357 MiB of Lua heap** in
this fixture. Efficient navigation does not solve the underlying history-memory
cost. Clipboard extraction remains synchronous and bounded by the clipboard byte
limit; its presentation latency was not measured here.

## Remaining qualification and product work

- Actual Linux desktop/Wayland, interactive non-US layouts, IME candidate UI,
  screen readers, monitor changes and suspend/resume need their own evidence.
- The implemented vi subset lacks paragraph motions, dedicated configurable vi
  maps, editing operators/registers/macros and other full Vim behavior.
- Plain-text URL hints and X11 primary selection remain unimplemented.
- Windows remains a separate required platform workstream.
- Native CI gates now invoke vi/selection smokes; this document records local
  executions, not an observed hosted CI run.
- No speed, power or complete feature-parity advantage over another terminal is
  established by these model benchmarks.
