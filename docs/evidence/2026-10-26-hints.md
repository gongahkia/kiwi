# Keyboard URL hint qualification — 2026-10-26

This qualifies bounded viewport URL discovery and explicit keyboard activation.
The seven-workstream request remains open in the [implementation ledger](../IMPLEMENTATION_TRACKER.md).

## Implementation and reproduction

Atomic changes: `7ca7520` adds discovery; `c7443cb` renders atlas-independent
badges; `63e204c` integrates actions and host input; `2cc4e71` charges OSC 8 URI
validation to the scan budget; `b7de80c` adds load benchmarks; `44a376b` preserves
the chosen target after rejected letters; `54b501f` adds native CI gates and waits
for frame-limited uploads in the fixture.

```sh
make check test-core
make hints-smoke hints-framebuffer-smoke
make bench-hints HINT_HISTORY=10000
```

Native fixtures require a graphical session. The input fixture drives the real
host callbacks/controller and a raw Python PTY receiver. Browser opening and
clipboard writes use private substitutes; no external browser is launched and
the user's clipboard is untouched. The only byte allowed to reach the child is
the deliberate `x` typed after hints exit.

Xvfb/software Vulkan does not establish hardware acceleration, desktop compositor
behavior, actual Wayland input, IME candidate UI or screen-reader accessibility.
CI workflows now include native hint gates; these results are local executions,
not an observed hosted CI run.

## Load measurements

Raw records: [macOS](2026-10-26-hints-macos.json),
[Linux](2026-10-26-hints-linux.json). Both use `54b501f`; macOS reports a clean
checkout, and Linux uses `git archive` with the full hash in `BUILD_REVISION`.
The archive has no Git metadata, so its environment probe reports an unavailable
revision. Linux was Ubuntu 24.04 with two CPUs and a 4 GiB memory limit. Runs were
sequential, without another Kiwi test workload running concurrently.

The fixture retains 10,000 history rows at 80 columns plus 24 screen rows. It
measures one model scan per case, including initial JIT/setup cost. Construction,
rendering, OS clipboard/opener latency and event-loop sleeps are excluded. Slice
percentiles describe steps within a single run, not repeated independent trials
or comparisons with another terminal.

| Case | Work units | macOS total CPU | Linux total CPU | Results |
| --- | ---: | ---: | ---: | --- |
| Visible link after 10,000 retained rows | 4,027 | 4.11 ms | 3.95 ms | 1 complete target |
| 64 distinct ~1,920-byte OSC 8 targets | 123,467 | 7.04 ms | 5.92 ms | 64, three label pages |
| 300 one-cell targets | 6,293 | 1.05 ms | 1.54 ms | 256, explicit match limit |
| 150 ~2,020-byte OSC 8 targets | 262,144 | 10.59 ms | 12.48 ms | 129, explicit scan limit |

Every step used at most 4,096 work units. The long-target case used 31 slices;
p95 slice CPU was 0.36 ms on each platform. The visible-link case used one slice,
approximately 4 ms, including first-use JIT overhead. Peak sampled temporary heap
was below 134 KiB in every case; retained growth after clearing and collection
was below 42 KiB. The benchmark guards temporary heap below 8 MiB and retained
growth below 1 MiB. Cancellation clears pending work and exposes no partial labels.

The terminal model itself still used approximately **236 MiB of Lua heap** and
259–271 MiB process RSS. Bounded discovery does not solve that history-memory cost.
These timings establish neither a displayed-latency guarantee nor a speed/power
advantage over another terminal.

## Remaining product and platform work

- URI policy remains ASCII HTTP(S)/mailto, up to 2,048 bytes. Unicode URLs,
  file/custom schemes, arbitrary hint regexes and custom hint commands are absent.
- Terminal output invalidates hints; they do not update targets silently while
  the user is choosing a label. Ctrl+R explicitly restarts discovery.
- Labels use a fixed bitmap alphabet and colours; configurable label appearance
  and separate accessibility exposure need further work.
- X11 primary selection, actual-desktop qualification, Windows, colour emoji,
  broad performance/power measurement and the remaining ledger items are open.
