## Independent oracle boundary

`make test-regex-oracle` compares 5,000 seeded generated ASCII cases with
POSIX ERE. It is included in `make check` and the minimal Linux CI job.
Queries anchor each candidate start, then constrain the suffix to check the
longest endpoint. This avoids a Darwin unanchored-search optimization that
skipped valid starts. A 60-second process alarm makes oracle stalls fail
explicitly; diagnostics identify the expression and input.

Darwin passes generated depth-3 patterns: 3,266,925 total Kiwi transitions,
22,148 maximum per case. Linux/glibc uses depth-1 generation: 736,402 total
and 2,943 maximum. Both use input lengths through 59 ASCII scalars.
This is an intentional coverage difference: glibc stalled on deeply nested
repetition, including a ten-character input. A test-only musl trial disagreed
on an endpoint where Darwin and explicit matching agreed; it is not a test
dependency. Linux complex-pattern oracle equivalence remains unqualified.
Both platforms still run the same product complexity tests and nested-repeat
large-history workload, including a saved case that stalled glibc.

## 10,000-line model workload

Commands, after `make native`:

```sh
LUA_PATH='src/?.lua;src/?/init.lua;;' luajit src/kiwi/bench/search.lua 10000
```

`make bench-search SEARCH_HISTORY=10000` is a convenience target. These are
CPU/model measurements, excluding window events, waits and GPU presentation.
Each case is one complete search; slice percentiles describe its cooperative
steps, not repeated-run uncertainty or displayed input latency. The query and
result limits are assertions, not timing-based pass/fail thresholds.

| Environment | Workload | Total CPU ms | p95 slice CPU ms | Max slice CPU ms | Peak temporary Lua MiB |
| --- | --- | ---: | ---: | ---: | ---: |
| macOS Intel | Absent literal | 219.6 | 0.376 | 2.461 | 1.55 |
| macOS Intel | Anchored Unicode regex | 270.1 | 0.316 | 2.389 | 1.63 |
| macOS Intel | Nested repetition, no match | 1535.9 | 0.441 | 2.217 | 2.84 |
| Linux container | Absent literal | 243.1 | 0.414 | 2.882 | 1.57 |
| Linux container | Anchored Unicode regex | 332.8 | 0.413 | 1.944 | 1.65 |
| Linux container | Nested repetition, no match | 1629.3 | 0.490 | 2.537 | 2.85 |

Every slice stayed within 4,096 charged operations; the nested-repeat scan
used 18,532,775 operations, below the 33,554,432 total cap. Match-limit tests
also stopped explicitly at 256 retained results. The benchmark asserts less
than 16 MiB temporary Lua heap and less than 1 MiB retained after cancellation.
Measured cancellation was 0.0010 ms on macOS and 0.0015 ms in the container;
post-cancellation heap deltas were approximately 272 KiB and 302 KiB.

Raw reports: [macOS](2026-10-25-macos-search.json) and
[Linux](2026-10-25-linux-search.json). macOS source was clean `24ff0bd`;
the Linux container used the `27b84b6` archive. Search-engine code was unchanged
between these revisions. Linux has no `.git` directory, so its report cannot
provide Git provenance; the archive revision was recorded in `BUILD_REVISION`.
The Linux container was limited to two CPUs and 4 GiB. These results are not
a comparison against other terminal products.

The first workload attempt exceeded the temporary-allocation budget. Search
now borrows each row once per slice, reuses logical-line arrays, and represents
NFA threads numerically in reusable buffers. The retained terminal history
itself still consumes substantial memory; this change does not solve that
broader performance workstream.

## Remaining product limits

The Find UI uses the window title and current-match highlight. It has no
in-grid search bar, index, case folding, Unicode properties, lookaround or
backreferences. It preserves existing stored gaps before wide-character wraps.
New output or resize invalidates results instead of maintaining a live index.
GTK GL integration is implemented but this fixture qualifies WGPU; physical
IME/desktop qualification, vi navigation, URL hints and primary selection
remain separate open work.
