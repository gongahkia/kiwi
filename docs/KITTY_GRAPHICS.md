# Kitty graphics protocol foundation

This is Kiwi's M7 parser/state contract for the Kitty graphics protocol. It is
an evidence-gated design artefact, not an implementation of image decoding,
texture allocation, rendering, image persistence, or a promise of compatibility
with iTerm2 or Sixel.

## Framing and accepted subset

The parser recognizes only 7-bit APC framing `ESC _ G control ; payload ESC \\`.
Both APC's string bound and this model's payload bound are 4,096 bytes. A
graphics command must be serialized: a transfer with `m=1` owns the next
graphics APC until a matching final `m=0`; any non-graphics terminal data may
continue normally, but another graphics action terminates that partial transfer
as rejected. Kiwi records no payload bytes after validation.

v1 accepts ASCII control pairs with one-character lowercase keys, no duplicate
keys, and printable ASCII base64 payload bytes only. It specifies these actions:

| Action | Accepted fields | Result in this phase |
| --- | --- | --- |
| `a=t` | `i`, `s`, `v`, `f=100`, `t=d`, optional `m` | bounded PNG transfer declaration, no decode |
| `a=T` | transfer fields plus optional `c`, `r`, `p` | declaration plus deferred placement |
| `a=p` | positive stored image `i`, optional `p`, `c`, `r` | deferred placement |
| `a=d` | `d=i` plus optional `i`/`p` | deterministic image or placement deletion |
| `a=q` | transfer declaration | validate-only result, no image/placement ownership |

Only inline direct transmission (`t=d`) and PNG format (`f=100`) are selected.
Raw RGB/RGBA, zlib compression, filesystem/shared-memory/file-descriptor
media, Unicode placeholders, relative placement, animation, frame composition,
virtual placement, and every unlisted control field are rejected. This avoids
decoding or opening an untrusted path before M7's cache/decoder issue.

## Bounds and ownership

The design limit is 64 image IDs, 256 placement records, 16 in-flight chunks,
4,096 APC bytes per chunk, 1 MiB declared encoded transfer bytes, and PNG
dimensions from 1 through 8,192 pixels in either dimension. IDs are unsigned
32-bit non-zero integers. A placement is owned by its `{image_id, placement_id}`
pair, where a missing/zero placement ID creates an anonymous bounded placement.

The transfer ledger retains only image ID, declared width/height, format,
accumulated byte count, continuation state, and local lifecycle/rejection
reason. It never retains image bytes, decoded pixels, paths, shared-memory
names, file descriptors, command text, or renderer handles. A complete valid
transfer establishes an opaque image declaration; it remains `undecoded` until
the later decoder/cache phase. A placement refers to that declaration but does
not alter terminal cells in this phase.

Deleting an image removes all of its placements and invalidates an in-flight
transfer with the same ID. Deleting an exact placement removes only that pair.
Unknown IDs and malformed deletions are no-ops with a bounded rejection record;
they never infer an ID or modify text/cursor state. Reset drops every ledger
record. Primary scrollback owns no image data: future placement work must keep
row anchoring separate and explicitly degrade when a row is evicted.

## Deterministic failures and responses

Malformed framing, duplicate/unknown fields, invalid base64 alphabet, absent
required fields, invalid dimensions, over-limit chunk/transfer/record counts,
out-of-order continuation, or unsupported media/action reject the entire
graphics command. No display state is created until the final `m=0` command
has validated. A query may report only `OK` or a bounded ASCII reason tied to
its supplied ID; ordinary transfers have responses suppressed in this phase.
Responses are generated by terminal state, never by a renderer.

## Fixture vectors for the implementation phase

| Vector | APC controls | Expected model fact |
| --- | --- | --- |
| png-transfer | `a=t,i=1,s=2,v=1,f=100,t=d,m=0` | one undecoded image declaration |
| chunked-transfer | first controls above with `m=1`, then `m=0` | one final declaration; intermediate data invisible |
| transfer-interrupted | `m=1`, then `a=p,i=1` | partial transfer rejected; no placement |
| place | `a=p,i=1,p=2,c=4,r=3` | one bounded deferred placement |
| delete-placement | `a=d,d=i,i=1,p=2` | exact placement removed |
| delete-image | `a=d,d=i,i=1` | image and its placements removed |
| malformed | duplicate `i`, unknown field, invalid integer | no state mutation; rejection counter increments |
| oversized | 4,097-byte APC or over-budget chunks | parser/model rejection; payload omitted |

## Implementation checklist

1. Add APC-G recognition and an action separate from generic APC discard.
2. Implement the pure bounded model and test every vector whole, split at every
   byte, and randomized chunk boundaries.
3. Add state-owned bounded response/rejection counters without terminal-text or
   cursor mutation; verify record/replay determinism.
4. Define explicit row-anchor/scrollback reconciliation before implementing
   placement cells.
5. In #132, validate and decode only a completed declared PNG into a cache with
   independent byte, pixel, image, placement, and GPU-resource limits.
6. In #131, expose an explicit renderer resource and render pass; no decoder or
   terminal state may allocate renderer-owned objects directly.
