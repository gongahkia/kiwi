Launch notes

Kumeyuri: animated Mermaid from one frame stream

Mermaid is already the lowest-friction way to sketch systems in text. Kumeyuri keeps that source format and adds motion that can survive terminals, READMEs, docs sites, static assets, and browser embeds.

The wedge

Most diagram tools split along a hard line: either the source is easy to write, or the output is expressive enough to explain time. Kumeyuri tries to keep both. The input stays close to Mermaid, but the renderer lowers every supported diagram into a deterministic frame stream before any backend sees it.

That frame stream is the wedge. Once the core knows what each frame means, terminal playback, SVG animation, GIF/APNG/WebP export, and browser rendering become output choices instead of separate products.

Why not just SVG?

SVG is a good publishing target, but it is not where every diagram is read. Engineers inspect diagrams in terminals, issue comments, READMEs, static sites, slides, and local previews. Kumeyuri treats SVG as one backend, not the center of the architecture.

The current core supports a partial Mermaid matrix: 11 animated diagram families, 17 static-only families, and 3 known upstream roots that are rejected intentionally. Each parser produces semantic AST data, layout produces stable coordinates, and animation produces ordered frames with marker metadata where animation is supported. Renderers can then pick the best surface for their environment.

What ships now

The CLI can render text, SVG, GIF, APNG, and WebP, and it has an interactive TUI player for animated timelines. kumeyuri watch redraws a file as it changes, which keeps the authoring loop short enough for live docs work.

The web side exposes a wasm-bindgen renderer, a typed TypeScript wrapper, and a <kumeyuri-diagram> custom element with controls. Static sites can use generated SVGs with no JavaScript, while richer docs can load the WASM player for live rendering and playback.

Design constraints

Kumeyuri does not claim full Mermaid parity. The compatibility matrix separates animated partial support, static-only partial support, unsupported roots, and schematic renderers where parser coverage is ahead of visual fidelity.

That constraint keeps parity testable. Static snapshots, animation hashes, sanitizer checks, raster snapshots, fuzz and negative fixtures, compatibility drift checks, Playwright browser coverage, and a WASM bundle budget all run against the same source tree.

Try it

cargo install --path crates/kumeyuri-cli
kumeyuri render demos/http-request-lifecycle.mmd --format svg \
  --theme github --dark-theme tokyo-night > request.svg
kumeyuri play demos/os-scheduler-state-machine.mmd --loop

The repo also includes a docs site, example gallery, launch demos, and a 60-second asciinema screencast covering CLI render, watch mode, and the web embed path.
